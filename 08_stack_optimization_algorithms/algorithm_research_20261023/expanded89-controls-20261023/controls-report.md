# 89层扩大训练云与可调层：四组预声明有限控制

日期：2026-10-23。本报告是已完成的四组固定预算光学研究，不是软件发布、生产验收或尚在进行的后续研究结果。公开软件数值基线为 [coating-sim fa987833](https://github.com/ii33/coating-sim/tree/fa9878336a597dc6df1db5b584bda3be4423cbca)。前轮原始资料保持不变。

固定原89层基线，每组32个独立有界均匀场景、89个物理厚度变量、原厚±1%搜索域，两个训练seed分别测试±0.5%和±1%工艺误差幅度。25次cloud/20次迭代仅是探索截点，不是收敛保证；±1%设计域与工艺误差界不是一回事。本轮沿用预先确定的目标和验收，未改损失、选择策略或追加实验。

全部4组设置、种子和验收先记录于predeclared-plan.json。每组从同一未被holdout挑选的原膜系开始。每次拟替换的训练可行incumbent均独立完整扫描原184600个nominal条件；不合格则保留此前完整可行方案，原始稀疏best另存。

本轮同时扩大训练样本与自由层范围，不能单独识别“少场景”或“6变量”的因果作用；也不以未改善证明物理不可行。任何后续匹配消融/预算或算法改变须另行预声明。

## 冻结版本与中断恢复

四组使用相同指定数值核心，后两组从[公开fa987833提交](https://github.com/ii33/coating-sim/tree/fa9878336a597dc6df1db5b584bda3be4423cbca)的独立冻结实验副本执行。第三组在开发核心变化时曾中断，不把中断输出当终态或热启动；按原预声明设置重新从原始89层基线完成。前两组请求一致，并在同一冻结依赖下重新正式物理重放。此处不复制源码文件hash清单、模块导入路径或开发日志，也不宣称整个持续开发的软件树一直未变。

历史来源IR上界曾以nextafter(.03,-inf)编码；本轮显式使用物理上界.03并保留原严格R<.03算子，避免重复缩一ULP，未增加工艺余量。原始历史来源不改写，本批仅保留紧凑设置与名义/留出汇总，不新增完整材料或优化请求载荷；原始完整材料与网格沿用既有公开研究基线。

## 成本、重放与边界

- 留出初次四线程批量遇到显著wall退化，而同时有后台开发测试争抢；具体GIL、带宽或过订阅原因未证实。完整已保存样本全部保留，旧执行器结束后剩余相同冻结job改为串行，双表达式批量也串行；仅最小固定集合用于真实四线程等价核。该调度调整没有换候选、场景或验收，观察时间不是干净性能基准，也不支持泛化“线程必慢”。
- 正式API每组估计结果/求解工作留存100.51MiB，小于256MiB护栏；不提高默认上限。完整原网格独立流式审计不是删点或冒充完整网格直接约束搜索。
- 优化前向、解析Jacobian工作数与额外full名义/holdout审计分别记录。时间包含独立资格检查和物理重放；共享环境观测值不是公平TFCalc速度比。
- 原始raw结果与外部保留checkpoint均按冻结请求正式物理replay核对；不放宽显式厚度界、严格IR R<0.03或原visible R≥0.99。
- 所有误差是预声明假设，未校准用户设备；材料n/k、全层扰动与原指标未偷偷改变。
- 此89层基线沿用3种冻结材料的tabulated k=0理想化模型；未用该研究替代真实工艺材料测量、吸收验证或实物产率试验。
- 当前只是固定层数/材料的局部精修，无全局或连续域证明；稀疏训练与完整审计的差异被显式记录，未用额外margin解决。
- 流式summary、真实场景云内并行、active constraint exchange、MPI/GPU均是需要另行决策和验证的建议，本四组控制没有实施这些生产改造；建议与未完成的独立后续研究不能冒充本轮成功。

## 下一步算法建议，不属于本轮已验证结果

1. 优先将完整nominal separation扫描发现的活动面回注局部求解工作集，保持同一原指标和严格算子。4组共61次资格检查（含初态）中25次被full拒收；±0.5%首拒集中在IR约3020–3022nm/51°，±1%首拒集中在visible724nm/51°。这支持先修复稀疏路径漏面，而非仅继续压低不具完整资格的raw训练loss。
2. 流式summary/分块值-Jacobian与工作集需先保证全声明场景和完整原nominal扫描后才更新可用incumbent，保留预算/取消回退与独立重放；不提高当前v1默认256MiB上限来伪装可扩展。
3. 在完整约束路径建立后，再预声明更大预算的质量-成本曲线，以及匹配seed的场景数/可调层数因素对照。此次同时改变两因素，不能证明哪一项是主要原因；不得据本轮holdout挑seed或调参后继续把它当最终验收。
4. 固定问题的1/2/4等worker真实场景云/Jacobian吞吐、QP串行部分和峰值工作内存应受控剖面后再决定CPU并行或HPC/GPU路线。保留双精度与目标判定，数量级加速是待公平测量的目标，不是现有结论。
以上是本轮证据引出的提案，不是已取得的效果。后续constraint exchange与更大预算控制使用各自独立计划和结果，本报告不纳入其进行中工作；GPU仅属评估选项，未在此实现或计时。
