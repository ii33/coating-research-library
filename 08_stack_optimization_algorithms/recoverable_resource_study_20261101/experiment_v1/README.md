`evidence/published-case-replay.json` 保存完整冻结输入和新审计输出；`manifest.json` 记录公开文件的大小与 SHA-256。验证方式：

```sh
python -m unittest -v test_artifact_store
python -c "from artifact_store import verify_manifest; verify_manifest('.', 'manifest.json')"
python replay_published_case.py --repo /path/to/coating-sim --case inputs/published-reference-case.json --output /new/location/replay.json
```

核心检出必须精确匹配上述提交且受跟踪文件干净。运行依赖见 `runtime.json`；没有 Qt、pytest 或在线合成要求。`validation_samples_multiplier=32` 是本次明确选择的重放参数：发布摘要每个 17 点窗口有 513 个加密点，即 `(17-1)*32+1`。原简化请求没有保存所有求解选项，因此本次是明确配置的新审计，不冒称完整重建旧执行环境。

## 可靠保存约定

输入和审计见证不可变；相同内容可幂等保存，不同内容拒绝覆盖。每个通过审计的候选应在继续搜索前保存完整设计、输入关联及审计输出；不只保存最后一轮或数字摘要。临时文件写完并 fsync 后原子发布，清单校验路径、大小和哈希。每个有限批次将完整脚本、协议、输入、候选、审计与清单同步研究库并复读，再继续长计算。

工具依赖文件系统的原子硬链接、重命名和 fsync 能力；不能保证操作系统、远端服务或磁盘从不故障。远端提交/复读才构成这里的持久检查点，本地保存成功不等同于远端保存完成。
