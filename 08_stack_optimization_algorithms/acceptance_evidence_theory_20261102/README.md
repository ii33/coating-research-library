# 评分证据的拒绝优先与有序查找

本研究说明一个**不改变光学目标与接受门槛**的工程优化：对已生成的评分证据，先检查是否已有违反原条件的反例；仅当反例检查允许继续时，才执行原有的完整证据校验。这个顺序优化评分验证开销，不跳过光谱仿真、独立审计或最终成功所需的完整证据。它不以缓存的通过标志、评分对象身份或单一最大误差授予接受。

## 接受契约与正确性边界

设 `C(request, score, audit)` 表示原完整性检查：覆盖形状、波长网格和顺序、目标及角度等元数据、各条件与原响应一致性、归约算术、以及适用时的独立审计元数据均合格。设 `P(request, score)` 表示逐条原条件检查：名义接受使用原始严格／包含等号规则；求解器可接受性另用原有归一化容差，不把它当成名义达标。

```text
原顺序：C ∧ P
新顺序：P ∧ C             # 布尔短路；P 为假时可直接拒绝
```

在同一个**冻结且检查过程无副作用**的请求与评分上，两者的接受布尔值相同：`P` 为假时无论 `C` 如何都拒绝；`P` 为真时仍必须通过完整 `C`。条件记录缺失、非法类型、缺项等常见结构异常按既有处理路径拒绝；即使条件列表为空或表面全通过，也不会因此跳过完整性验证。上述推理不把任意抛出非契约异常或有副作用的自定义对象纳入保证范围。

每次调用重新检查当前内容，不按对象身份缓存结论，因此同一个可变评分对象在调用之间被修改后不会复用上次通过结果。**不保证**其他线程在一次检查进行时同时修改该对象的原子快照或并发一致性；调用方仍应冻结或同步证据。完整性校验核对所提供证据的结构及算术，并不是独立物理实验，也不替代正向计算或材料测量。

## 查找与数据语义

- 波长存在性检查直接对已有有序 `Sequence` 使用二分定位及相邻候选检查，避免为每个待查点复制整段波长列表。
- 附加审计点的响应查找仅在原覆盖已验证为严格升序、且该条件标识已在经验证的审计波长集合内时使用 `bisect_left`；不更改响应值或采样点。
- 运行时映射检查使用 `collections.abc.Mapping`，保留合法映射实现（包括 `UserDict`）的兼容性，不采用对象身份推断可信状态。
- 原有坐标识别的 4 ULP 规则仅用于识别相同采样波长，**不放宽 R/T 等物理值的门槛**。名义值目标、严格不等号和求解器容差各自保留原语义。
- 均值和 RMS 按声明的固定密网格与既有归约口径计算；额外偏移／极值审计点只提供逐点证据，不重新赋予积分权重。

二分替换部分线性查找、避免重复复制，不代表完整验证整体必然为 `O(N)`：接受路径仍需遍历全部必要证据，某些查找可为 `N log N`；开销受目标数、角度、网格、数据结构及输入状态影响。这里不宣称普适速度倍数、减少审计点、改变光学计算或跳过最终证据。

定向测试覆盖名义与求解器容差、严格边界、均值、审计、元数据、缺失／重排和可变评分；参考与新实现分别在独立进程中对规范证据、篡改证据及语义边界作接受布尔值比较。定向测试与官方静态检查记录通过，但这并非所有可能输入、并发变异或独立物理模型的证明。软件 CI 状态须以对应提交的实际工作流为准，此处不声称全绿。
